# Brief contracts

Use relevant fields in the project's canonical brief. These are prompts for judgment, not a requirement to manufacture pages, personas, claims or features.

## Strategy and journey entries

```markdown
- Completion or recovery experience:
- Mobile/accessibility considerations:
- Observable success signal; proposed target only if useful:

Sitemap / navigation:
Route or anchor / visitor purpose / entry and onward paths / justification.
```

A gallery commissioner might enter a project detail from a referral, inspect scale and finish, check the artist's commission process, and send an enquiry. That calls for useful images, accurate captions and a low-friction contact path. It does not imply pricing tiers, a customer-logo strip or a metrics panel.

Explain the causal sequence. For example, show a commissioned object's setting before process detail if context is necessary to judge fit. Do not prescribe that sequence for unrelated sites.

For repeated case studies, define the shared narrative and required evidence once, then list actual projects and differences. An absent result becomes a pending content item or a qualitative description of verified work, not an invented percentage.

## Content and proof

```markdown
| ID | Claim, content or asset role | Source/file | Permission | Status | Used by |
| --- | --- | --- | --- | --- | --- |
```

Use statuses such as verified, supplied-unverified, proposed, missing, and not applicable. A user-supplied claim can be accurately recorded as supplied while verification or publication permission remains pending. Distinguish asset existence from permission to use it.

For customer quotes, logos, certifications, awards, project results, availability, pricing and brand history, retain a source. Link each supporting section to its proof ID. Placeholder copy must be visible as draft in the review package and must not become a published factual claim.

Specify only content-management needs that affect implementation: who updates which content, frequency, localization, structured fields, search intent or existing URLs to preserve. Metadata, redirects and indexing matter when in scope; do not generate unsupported SEO promises or keyword-volume estimates.

## Acceptance criteria

Use observable results instead of adjectives. Separate page behavior from global technical checks and exact visual rules.

- Weak: `Feels premium; fully responsive; fast.`
- Useful: `A visitor entering P2 can identify the commissioned work, open verified detail images and reach the enquiry destination without returning home.`
- Useful: `At the agreed narrow viewport, artwork captions follow their images in reading order and the primary contact action remains reachable without hover.`
- Useful: `A submitted enquiry shows a real success state only after delivery succeeds; a failure preserves input and explains recovery.` Use only if a form exists.

Choose measurable accessibility and performance targets for the actual audience, content, stack and test conditions. Record the viewport, browser, device/network profile or tool necessary to verify a technical target. An aspirational target is not a measurement.
